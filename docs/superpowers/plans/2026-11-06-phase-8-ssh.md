# Phase 8: SSH Projects — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A remote machine as a project: add an SSH host and directories on it, and their terminals (tabs and splits included) run there, in zmx there, so they outlive a dropped connection and Yatty quitting. Key or password logins. agentree's SSH projects.

**Architecture:** Pure `SSH` helpers (agentree's `src/services/ssh.ts`: valid hosts, ControlPath directory, ssh argv in batch or tty mode wrapped in `sh -c`, `~` paths, ssh config hosts, the askpass helper, error messages) unit-tested. `StoredState.hosts: [SSHHost]` (host, remote `$HOME`, remote zmx path, `needsPassword`, directories) listed in the sidebar like repositories. A remote directory is a `Worktree` with `host` set; its id is `ssh:<host>:<path>`, so zmx session names, layouts and labels key off it unchanged. A remote pane's command is `ssh -t <shared master> -- host 'exec sh -c "cd DIR && ZMX_DIR=… exec ZMX attach SESSION"'`.

**Spec:** roadmap Phase 8; agentree DEVLOG "SSH projects", `src/services/ssh.ts`, `src/ui/SshModal.tsx`, `test/helpers/fakebin/ssh`.

## Global Constraints

See the roadmap. Every ssh call shares one master connection per host: `ControlMaster=auto`, `ControlPersist=10m`, `ControlPath=<dir>/%C` with `<dir>` the first short enough (socket paths cap at 104 bytes) of `~/.local/state/yatty/ssh` and `/tmp/yatty-ssh-<uid>` (ours, mode 0700), else no sharing. Background calls run in batch mode (`-T -o BatchMode=yes -o ConnectTimeout=10`); for a `needsPassword` host they run only when `ssh -O check` says the master is up, so polling never fails a login. Commands sent to a host are wrapped in `sh -c` (the remote login shell may be fish). The remote zmx is found once, at probe time, through the user's login shell (`$SHELL -l -c 'command -v zmx'`: a non-interactive ssh has a thin PATH) and stored with the host; remote sessions live in zmx's own default directory there. Remote panes start a plain shell; "New Agent Tab" types plain `claude` (the status hooks are files on this Mac). Git status, pull requests, diffs, merging, New Worktree and the `yatty` CLI don't apply to remote directories and are hidden or disabled for them. Passwords are never stored or logged: the secret travels only in the probing ssh's environment, answered by an askpass helper that holds no secret and refuses anything but a password or passphrase prompt.

## Review Focus

1. A host or path can't become an ssh option or a second command: hosts starting with `-` or holding whitespace are refused; paths with spaces, quotes, `$`, `;` or a leading `~` reach the remote `cd` as one word — test on `SSH.remotePathExpr` and the attach argv run through a fake ssh.
2. A password host is never logged into by a background call — test on the batch-call guard with a fake ssh that logs attempts.
3. The askpass helper answers only password and passphrase prompts — test by running it with a host-key question and a one-time-code prompt.
4. Removing a directory or host kills exactly its remote sessions (when connected) and never touches remote files; local reaping never kills remote sessions.
5. Nothing local-only runs on a remote directory: no local git, gh, diff or zmx call with a remote path — test that the git status, PR and diff entry points skip a `Worktree` with `host`.
